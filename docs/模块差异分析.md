# 独立模块差异分析

`--mode differences` 实现了 [改造建议](../advice.md) 中的独立比较路径。原有 `--mode holes` 保留实例未覆盖主项及其对照、限量前缀和候选排除流程。新模式先按定义/指标模型分组，顺序读取每个实例的原生描述符和状态，再为共享覆盖点分类，不生成完整实例空洞主项。

```bash
python3 uncover_extract.py \
  --mode differences \
  --vdb merged0608.vdb --rtl-root rtl \
  --metrics line tgl branch cond \
  --out results/module-differences
```

默认工作盘为系统临时目录，结果目录仍由 `--out` 指定。每实例遍历核对完整目标描述并独立读取状态；模型身份不足时按实例隔离，结构缺失或不同的目标明确记录不可比原因。不会仅凭 checksum 跳过目标核对，也不保留跨遍历的原生子句柄。

## 数据与报告

源码和完整原生定位在模型组内每个目标只保存一次；每个实例用编号关联原生 `covered/coverable/raw_status`。超出 SQLite 有符号整数范围的值以十进制文本无损保存。模型目标按照实际完整定位对齐；不同信号位、方向和原生 bin 不因同名或同行而合并。

各点分成全体已覆盖、共同未覆盖、展示状态不同和共同特殊状态；不可比为独立属性。全体已覆盖与共同未覆盖只汇总；有差异、特殊状态或不可比情况的点进入明细。单实例与未知身份明确标记，不作为多个实例一致的证据。

`report.md` 按模型及精确实例状态分布归组；同一组的完整实例路径只列一次，随后列出每个具体覆盖点。`module_summary.json` 提供模型、实例和源码目录，`difference_patterns.jsonl.gz` 提供分组，`differences.csv` 与 `differences.jsonl.gz` 保存覆盖点对分组的引用。`coverage_facts.sqlite` 保留全部紧凑原始事实，可离线重新导出。

这版使用有界批量 SQLite 状态数组，没有把每个目标简化为覆盖布尔值。对齐成功时不再计算和写入重复目标摘要，也不在比较阶段重新访问 NPI；状态比较保留现有展示口径。输出减少并不意味着跳过必要实例状态读取。

保留状态库约 790 MiB；worker 峰值 RSS 约 2.59 GiB。worker 时间包括事实库复制到输出目录，不包括父进程之后的独立 URG 核验和最终工作区回收。运行时的工作区与结果库复制会同时占用空间，文件大小不等于磁盘峰值。

这是当前机器上的一次全设计运行，不能作为三轮中位数；四指标与旧的 Toggle 单指标基准不作直接加速比计算。完整命令、输入和分项计时保存在 manifest，逐点核验记录见 `validation/module-differences-equivalence.json`。

本次节省 720.562 秒，约 12.01 分钟；耗时减少 64.2%，速度约为历史运行的 2.79 倍。新路径将初始空洞扫描及重复原子枚举替换为一次完整原生扫描，363.638 秒内完成描述核验及状态暂存，之后状态比较 29.956 秒，事实库发布 1.780 秒，报告写出 4.534 秒。共享描述成功复用 6,762,534 次，只序列化 817,618 个目标描述；必要状态数未减少。

这是一次历史运行与一次当前运行的对照，未交替运行三轮，机器负载与缓存条件不同，不能解释为稳定三轮加速比。新旧输出组织也不同；等价核验覆盖目标定位、实例原始事实、差异集合及原生总计，不要求文件逐字节相同。完整记录见 `validation/module-differences-performance.json`，报告见 [Toggle 结果](../validation/module-differences-toggle/report.md)。
