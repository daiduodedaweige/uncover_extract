# 输出格式与内部流程

主程序统一执行“模型分组 → 每实例顺序遍历 → 原生事实保存 → 模型目标分类 → 实例分布汇总”，没有模式切换。默认工作盘为系统临时目录，原生工具始终在副本及独立进程中运行，复核输入后发布完整结果；可选 URG 核验在发布前执行。

## 目标身份与范围

模型分组要求定义及指标模型身份；身份缺失时按实例隔离。同组第一个所选实例建立目标目录，其余实例逐条核对实际完整定位，匹配时复用目标编号。缺失、额外或描述变化的节点回退完整定位匹配，并保留不可比原因。每个实例自己的状态由 NPI 读取，不保留跨遍历的原生子句柄。

范围采用所选实例实际覆盖点的并集。同模型范围外实例也保存事实，但其独有目标不扩大报告范围。源码引用相同而模型不同的实例作为不可比对照。单实例和身份未知组明确标记，不能作为多个实例覆盖一致的证据。

XML 只提供已知版本的定义、源码引用及模型 checksum 提示。状态与计分值来自 NPI；不会解析命中位串。源码映射缺失或歧义不会删除覆盖目标。

## `coverage_facts.sqlite`

事实库结构版本为 1.0，可用 SQLite 或 Python 标准库只读查询，无需许可证。

| 表 | 内容 |
| --- | --- |
| `metadata` | 数据库指纹、测试引用、配置与比较依据 |
| `instances` | 实例编号、完整路径、是否属于所选范围 |
| `models` | 模型组编号、指标和模型身份 |
| `scopes` | 每实例/指标的原生总计和实际枚举数量 |
| `sources` | 源码编号、原路径和当前路径映射 |
| `targets` | 覆盖点编号、参考顺序、源码/行号、完整定位、代表实例、是否属于报告范围 |
| `states` | 实例编号 + 目标编号 → covered、coverable、raw_status |
| `classifications` | 模型目标的展示分类及不可比属性 |
| `patterns`、`findings` | 精确实例状态分布分组及覆盖点引用 |

原生三元组无损保存，超出 SQLite 有符号 64 位范围的整数以十进制文本保存，读取时恢复 Python 整数。批次由 `--batch-size` 控制，默认 256，范围 1–500；SQLite pager 约 16 MiB，分批提交。整个 worker 的内存还包含 NPI 库及原生模型。

`states` 保留所需模型各实例参与分析的原始事实，包括已覆盖、未覆盖、不可达、不计分、非法及未知状态。原生编译时或报告时排除的实例覆盖点不参与分类和计数，不进入报告、导出或发布的事实库；若该目标在所有实例中均被排除，目标描述也删除。部分实例排除时，只比较其余实例，不将排除实例视为未覆盖或不可比。原始完整定位仍用于扫描阶段的目标对齐，过滤不会改变后续目标的对应关系。读取错误会导致失败，不会用“未覆盖”代替读取失败。

## 分类与分组报告

| 分类 | 含义 |
| --- | --- |
| `all_covered` | 所有已对齐实例的展示状态均已覆盖 |
| `common_uncovered` | 所有已对齐实例均为常规未覆盖 |
| `different` | 实例间展示状态不同 |
| `common_special` | 所有已对齐实例均为相同的不可达、不计分、非法或未知状态 |

先过滤原生排除点，随后按非法、不可达、计分值的顺序判定展示状态：`covered/coverable=1/1` 为已覆盖，`0/1` 为未覆盖，分母为零的不计分，其余无法识别的值为未知。比较的是同模型同一原子目标的逐实例状态，不比较模块覆盖率；信号位、方向和 bin 分开处理。

不可比是独立属性，可与上述分类重叠。缺失目标不当作未覆盖；有不可比实例时，分类不能代表这些实例的状态。

全体已覆盖及共同未覆盖只进入汇总；有状态差异、不可比或共同特殊状态的点进入明细。分类采用展示状态，原始标志不同但展示状态相同不会自动扩大差异集合；原始证据仍在事实库中。

- `module_summary.json`：模型、实例和源码目录；各分类计数；不可比目标数量；单实例及身份不足标记。结构版本 1.0。
- `differences.jsonl.gz`：每条明细包含 target/model 编号、指标、源码/行号、具体目标、pattern 引用及分类。
- `difference_patterns.jsonl.gz`：每组的实例编号到展示状态分布、不可比路径/原因和目标数。
- `differences.csv`：对应明细表。
- `report.md`：开头以“模块 / 实例 / 未覆盖点数”列出存在常规未覆盖点的所选实例，每个实例合并各指标的原子覆盖点计数，包含共同未覆盖点，忽略已覆盖及特殊状态。随后保留分组明细，同一实例分布只列一次，以“实例 / 覆盖情况”两列表格逐实例展示状态和不可比原因，再列出具体覆盖点。

报告包含分类依据。“源码文件”列显示解析后的当前文件路径，链接使用相对于报告的文件路径，不带行号锚点；行号在独立列中以纯文本展示。显式前缀映射优先，其次使用指定的 RTL 根；指定目录中缺失或存在歧义时不回退旧构建路径。未指定 RTL 根或匹配的前缀映射时才直接使用原路径。缺失或映射歧义的源码保留原路径文字，不生成链接。纯 Line 表格省略具体目标列，CSV/差异 JSONL 的 Line 展示描述也留空。Toggle 保留信号位和方向，其他指标保留 bin 描述。完整原生定位及原始源码路径保存在事实库及离线完整记录中。

## `analysis_manifest.json`

manifest 格式版本为 2.0，工具版本为 0.2.0。默认输出从逐实例空洞主项改为共享事实与模块差异报告。

`input` 保存 VDB 路径、版本、逐文件 SHA-256、整体指纹和原输入未变核查结果。`configuration` 保存实际配置，无 `mode` 或旧比较缓存参数；`available_tests`、`selected_tests` 区分可用与采用的测试。

`summary` 按指标记录：

| 字段 | 含义 |
| --- | --- |
| `native_covered/native_coverable` | 所选实例本层原生计分汇总 |
| `uncovered_candidates` | 所选实例的常规未覆盖原子目标数 |
| `visited_atomic_bins` | 所选实例参与分析的原子目标数，包含特殊状态，已过滤原生排除点 |
| `visited_*` | 各展示状态的实例原子目标计数 |
| `difference_count` | 状态不同的模型覆盖点数 |
| `output_count` | 差异/特殊/不可比明细总数，按模型目标计 |
| `scopes`、`scope_count` | 所选实例本层原生总计和范围数量 |
| `nonstandard_state_inventory` | 参与分析的特殊状态保存在事实库的说明 |

`same_rtl_comparison` 保存唯一模型目标数、差异数、不可比数、分组数和事实库文件名。`urg_validation` 记录独立核验结果，未请求时为 `not_requested`。旧的候选排除导出/验证字段已移除。

`performance.timings` 保存指纹、副本、原生会话启动及以下主要阶段：

- `fact_scan_seconds`：原生顺序读取、完整描述核验及状态暂存。
- `fact_comparison_seconds`：从已保存状态分类和分组。
- `facts_publish_seconds`：事实库复制到输出暂存目录。
- `output_seconds`：分组报告、JSON、CSV 及 gzip 写出。

`performance.comparison` 保存索引时间、原生实例原子读取数、描述实际序列化数、完整描述复用数及状态读写批次数。`total_seconds` 为 worker 总耗时，`peak_rss_kib` 为其峰值 RSS；不包含父进程后续的独立 URG 和最终工作区清理。计数中不包含的阶段不能据此视为零成本。

## 离线导出

```bash
python3 -m uncover_tool.export_facts \
  --result results/coverage --kind holes \
  --out results/all-holes.jsonl.gz
```

`--kind` 支持 `holes`、`differences`、`common-uncovered`，读取已保存的事实库，不调用 NPI。输出 JSONL 或 gzip JSONL，拒绝覆盖文件。

`holes` 每个所选实例的常规未覆盖点一条，保留：

- `target_id`、`database_id`、`test_scope_ref`：由输入指纹、测试范围、实例、指标及完整原生定位关联目标。
- 完整实例、模块/模型、源码行号及当前源码映射。
- `covered/coverable/raw_status`、独立 `flags` 及展示状态。
- `native_locator` 和 `target`，Toggle 额外记录信号与方向。

空洞按模型覆盖点/实例顺序导出，不内嵌重复的整组对照。其 ID 不承诺跨数据库、跨编译或跨测试集合稳定。

另两种导出每个模型目标一条，展开完整定位与逐实例原始状态及不可比原因。`common-uncovered` 的范围依据可比实例分类，仍需查看不可比属性。

已有外部排除在原生读取前加载，带原生排除位的实例覆盖点随后过滤。URG 只核对完整设计、相同测试及外部排除下的精确计分值，不构成 RTL 不可达性证明。
