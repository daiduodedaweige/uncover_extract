# 输出格式与内部流程

## 核心流程

```text
命令行检查 → 暂存目录 → 独立原生进程 → 输入全内容指纹与副本
    → 选择/累计测试、加载已有外部排除
    → 原生指标探测与全范围扫描
    → 确定性选择、兼容实例比较
    → 可选候选排除导出、全新副本重新加载验证
    → 原输入复核 → 流式输出
    → 可选 URG 独立计数校验 → 成功后发布结果目录
```

XML 仅提供版本已知的定义、源码引用及模型 checksum 提示。命中数据、计分值和状态由 NPI 读取，既不依赖 `testdata/test` 名称，也不自行解释位串或命中次数编码。XML 提示未知时，相应实例模型不比较，原因写入结果。

## `uncovered_coverage.json`

顶层结构为 `{"schema_version":"1.0","records":[...]}`。`records` 仅保存输出的未覆盖原子目标；多个指标按用户指定顺序，指标内按原始源码、完整实例、行号和原生定位排序。限量输出是全量顺序的前缀。

| 字段 | 含义 |
| --- | --- |
| `target_id` | 当前数据库内容指纹、测试范围、实例、指标及原生定位生成的 SHA-256 标识 |
| `database_id`、`test_scope_ref` | 输入内容指纹与所选测试名称集合引用；测试累计仍由 NPI 执行 |
| `metric`、`scope_kind` | `line/tgl/branch/cond`；实例本层视图 `instance_self` |
| `instance_path`、`module_name`、`model_id` | 完整层次、定义名、可获得时的定义与指标模型身份 |
| `source_file`、`start_line`、`end_line` | 原生对象提供的源码文件与行号；缺失时为 `null`；当前不推算多行语句范围 |
| `source_mapping` | 原路径、当前候选、映射方法/状态、当前文件 SHA-256、对应关系未确认说明 |
| `covered`、`coverable` | 工具的原子计分值，不是执行次数 |
| `raw_status`、`flags` | 原始状态位及独立解释；覆盖、排除、不可达等证据分别保留 |
| `status` | 便于筛选的展示状态，不替代原始位和计分值 |
| `target` | 原生对象名称、结构定位及具体 bin；Toggle 额外保留位信号与方向 |
| `native_locator` | 当前模型内的子节点下标及类型、名称、源码位置；重定位时核对描述，不只依赖下标 |
| `same_rtl_coverage` | 可选的对照实例、原始状态、不可比原因及目标状态差异 |
| `exclusion` | 可选的实例联合原生记录，以及所选候选在实例/指标下的预期影响定位 |

`target_id` 仅用于该数据库和测试选择下的追溯；输入内容发生变化或测试集合不同，标识也会不同。它不承诺跨编译、跨工具版本或加入排除后的跨库稳定性。

现存 `validation/` 结果中的当前源码路径已随工具目录迁移更新：`source_mapping.path` 和 `candidates` 指向现位置，发生迁移的映射使用 `method=relocated_path`；CSV 的 `mapped_path` 同步更新。`original_path`、`source_file`、原生定位、目标 ID、原始运行配置和日志保留历史值，目录迁移不改变已有覆盖事实。

历史验证产物已做精简，当前保留报告、审计与基准摘要及最新原生/全设计结果；具体目录范围见 [验证资料说明](../validation/README.md)。

## `analysis_manifest.json`

`input` 保存数据库路径、版本、逐文件 SHA-256、整体指纹和原输入未改变的核查结果。`configuration` 保存真实命令配置；`available_tests` 和 `selected_tests` 区分可用与实际采用的测试。

`summary` 按指标保存：

- `native_covered/native_coverable`：选中实例范围的原生计分汇总，每个实例仅统计本层目标。
- `uncovered_candidates`：扫描出的、状态符合常规未覆盖定义的原子目标数量。
- `output_count`：应用可选限量后的主项数量，不包含对照行。
- `visited_atomic_bins`：扫描实际访问到的叶目标数量；默认剪枝跳过完整覆盖或无可计分目标的子树，因此不能当作模型全部 bin 数。
- `scopes`：各实例本层计分值，用于追溯与核对。
- `nonstandard_state_inventory`：是否显式请求了其他状态的完整原子清单。

`exclusion_validation`、`exclusion_export` 和 `urg_validation` 分别记录各可选阶段的实际状态。未请求时记录 `not_requested`；失败运行只保留诊断，不发布成功结果。

`performance` 保存分阶段耗时及子进程峰值 RSS（Linux 下 KiB）；其中包含原生库内存，并非仅 Python 对象大小。全量候选/输出使用 SQLite 暂存并流式写出；限量模式只暂存确定性前 N 个候选，但仍扫描全部范围以给出完整统计。

`performance.comparison` 保存实例比较的细分统计：

- `index_seconds`：源码引用与模型实例索引的构建时间，现已计入合并的 `selection_and_comparison_seconds`。
- `input_records`、`unique_model_targets`、`comparison_hits`：比较输入主项数、需要新计算的唯一模型目标数及复用的比较结果数；`all` 模式包含输出主项阶段和全目标阶段。
- `planning_seconds`、`native_read_and_cache_seconds`、`assembly_seconds`：任务规划、原生定位读取及状态缓存写入、对照结果组装耗时。缓存写入包含序列化，不能将读取与缓存时间直接当作纯 NPI 调用时间。
- `native_state_reads`、`state_hits`：比较任务实际读取的实例目标状态数、从状态缓存取得的实例目标数。`all` 另有 `enumerated_state_reads`、`enumerated_state_hits` 和 `all_inventory_seconds`，记录全目标遍历及其快照复用。
- `cache`：LRU 命中、SQLite 命中和未命中次数。`memory_cache_entries`、`memory_cache_capacity` 记录最终内存缓存条目数和上限；单批任务仍有临时数据，条目上限不是整个进程内存的字节上限。
- `inventory_atomic_targets`、`inventory_duplicate_targets`、`inventory_records_serialized`、`inventory_insert_batches`：`all` 原子枚举数、重复模型目标数、实际序列化/插入的唯一目标数及插入批次数。每个实例仍读取自己的原生描述符；重复模型记录在批量查询后省去序列化与插入。
- `inventory_identity_hits`：完整描述符签名命中有界身份缓存的次数。这层缓存仅在 `all` 枚举期间存在，上限同 `--comparison-cache-entries`；与状态/结果 LRU 分开计数，枚举结束后清空。
- `locator_strategy`：单个目标使用原有按需定位，多目标使用共享前缀树；`single_target_max` 保存当前阈值 `1`。`single_traversals`、`batch_traversals` 记录采用的路径。
- `gzip_output_seconds`：`all` 中差异记录的筛选、JSON 序列化及 gzip 打开、写入、关闭耗时；不含定位、比较组装、SQLite 提交或进度打印。
- 启用 `--profile-comparison` 后，额外记录 `child_handles_calls`、`returned_child_handles` 和 `released_child_handles`。这些计数只覆盖比较定位，未包含前置扫描和 `all` 的原子遍历。

未发生的计数可能省略。关闭比较时 `performance.comparison` 为 `{"mode":"none"}`，不创建比较器和比较缓存。`performance.timings.output_seconds` 保存最终 JSON、CSV、Markdown 及可选输出的整体写出时间。

`all` 模式的 `same_rtl_comparison.jsonl.gz` 在比较循环中写出，其独立计时保存在 `performance.timings.comparison_output_seconds`，与 `performance.comparison.gzip_output_seconds` 相同。它仍包含在原有 `selection_and_comparison_seconds` 中，以保持该字段语义。`output_seconds` 保留最终 JSON、CSV、Markdown 及 other_states 的写出耗时；新增 `output_total_seconds` 为这两项输出计时之和，不能再与它们重复相加。当前实测见 [继续优化验证](../validation/comparison-continuation.md)，上次恢复记录见 [比较性能验证](../validation/comparison-performance.md)。

比较缓存以完整原生定位描述及实例/模型身份区分目标，存储状态快照而非原生句柄。缓存使用独立会话命名空间，且在可能修改排除状态前关闭。批量定位仍核验每个实际访问路径的类型、名称及源码位置；自身目标不匹配继续导致失败，对照目标不匹配继续作为不可比原因保存。

## 特殊状态与校验边界

默认输出不会将已有排除、不计分对象、非法对象或不可达标记直接认定为常规覆盖空洞。需要逐原子保存这些事实时使用 `--include-other-states`，结果写为 gzip JSONL。原始状态的多个标记可以同时为真。

排除验证只核查报告声明的选中/兼容对照实例中的原子目标；URG 对照核查完整设计、相同测试集合和外部排除口径下的精确计数。两种检查作用不同，都不能据此推导一般的 RTL 不可达性结论。
